This gate verifies that the Person 1 input source and baseline, Person 2
geometry provider, Person 3 replay/proximity/rules, and Person 4 orchestration
interact through the existing frozen contracts. The evidence is synthetic and
replay-based. It does not establish public-data, live-tracking, Gate 6, or
Gate 7 completion.

that calls real P1, P2, and P3 algorithms, exercises the required scenario
behaviors, and produces outputs linked to source events and configuration.

## Integrated path evidence

`run_scenario` exercises the following real implementation path:

1. `ScenarioFrameSource` loads the manifest, RGB-D frames, masks, and track annotations.
2. `BaselineBuilder.fit` builds the P1 `BaselineArtifact` from baseline frames.
3. `ReplayTracker` reconstructs P3 tracks; the orchestration applies saved metric
	 positions, updates shelf proximity, carries forward near-shelf state, and
	 combines replay and saved occlusion masks.
4. `ShelfGeometryProvider.detect_changes` performs P2 registration, signed
	 change detection, occlusion handling, clustering, volume estimation, and
	 temporal confirmation.
5. `evaluate_removal_alert` applies P3 proximity, authorization, system-mode,
	 volume, and two-second association rules to produce `AlertEvent` objects.
6. The returned result includes serialized shelf configuration, source event
	 identifiers, geometry events, and alerts.

Camera drift is explicitly asserted in
`test_camera_drift_does_not_produce_false_removal`: expected and actual change
types are empty and the alert count is zero.

The existing `BoundedFrameQueue` tests verify a maximum size of two, oldest-frame
drop behavior, and preservation of dropped frame IDs and timestamps. Those tests
cover the existing bounded mock pipeline; `run_scenario` consumes a complete
finite replay rather than using that queue.
